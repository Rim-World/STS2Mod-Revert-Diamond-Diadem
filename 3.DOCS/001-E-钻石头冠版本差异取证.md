## 1. 结论速览

“钻石头冠”是 **Ancient 稀有度遗物**（中文界面称“先古遗物”，代码枚举 `RelicRarity.Ancient`），由 Ancient 事件 NPC 的遗物交换事件“Nonupeipe”提供（9 选 3 选项之一），也在事件遗物池中。两版获取渠道、稀有度、ID、标题、flavor 完全一致；**变的只有战斗内效果、效果文本和专属 buff 类**。

一句话总结：107 是“**节流换减伤**”——每个玩家回合结束时结算一次，若该回合打出 ≤2 张牌，施加专属 buff `DiamondDiademPower`，使持有者在下个敌方回合受到的普通攻击伤害减半；111 改成“**开战发糖**”——仅在战斗第 1 个玩家回合开始时一次性获得 20 点格挡 + 1 层复用自残影卡的 `BlurPower`，此后整场战斗无事发生。

### 2.2 专属 buff DiamondDiademPower —— 仅存在于 107

文件：`decompiled-107/MegaCrit.Sts2.Core.Models.Powers/DiamondDiademPower.cs`（41 行）。**111 版已彻底删除**（`decompiled-111/MegaCrit.Sts2.Core.Models.Powers/` 下无此文件；`AbstractModelSubtypes.cs` 中 111 只剩 `_t1420 = typeof(DiamondDiadem)` 一条，107 则另有 power 条目位于第 3341 行）。

```csharp
public sealed class DiamondDiademPower : PowerModel
{
    public override PowerType Type => PowerType.Buff;
    public override PowerStackType StackType => PowerStackType.Single;

    /// <summary> cuts damage received in half. </summary>
    public override decimal ModifyDamageMultiplicative(Creature? target, decimal amount, ValueProp props,
        Creature? dealer, CardModel? cardSource)
    {
        if (target != base.Owner) return 1m;
        if (!props.IsPoweredAttack()) return 1m;
        return 0.5m;
    }

    public override async Task AfterSideTurnEnd(PlayerChoiceContext choiceContext, CombatSide side,
        IEnumerable<Creature> participants)
    {
        if (side == CombatSide.Enemy)
            await PowerCmd.Remove(this);
    }
}
```

语义解读：

- Buff 型、单层不可叠加；
- 减伤只作用于**普通攻击伤害**：`IsPoweredAttack()` 定义为「带 `Move` 标志且不带 `Unpowered`」（见 §4.c），即攻击卡与怪物攻击的标准路径；毒、HP 流失、遗物/药水直伤等不受影响；
- 持续窗口：玩家回合结束时施加 → 敌方回合结束时移除。主要保护“下一个敌方回合”。

证据补充：`1.STS2-107Reference/filelist.txt` 第 13886 行含 `src/Core/Models/Powers/DiamondDiademPower.cs`、第 14176 行含 relic 本体；`2.STS2-111Reference/filelist.txt` 只剩 relic 本体一行。

### 2.3 BlurPower（111 版新效果复用的现成 buff）

文件：`decompiled-111/MegaCrit.Sts2.Core.Models.Powers/BlurPower.cs`。与卡牌“残影”（`Blur` 卡）共用同一 Power：`ShouldClearBlock` 返回 false 保护格挡不被回合开始清除；每到自己回合开始 `Decrement` 减一层。107 版同名类也存在（供 Blur 卡使用），但 107 的头冠未引用它。

## 3. 机制细节取证

### a. TurnNumber 起点（决定 111 版到底触发几次）

`PlayerCombatState.TurnNumber`（两版同义）：`decompiled-111/MegaCrit.Sts2.Core.Entities.Players/PlayerCombatState.cs:37`，XML 注释明言 “This starts at 1”。开战的第一回合不经过 `SwitchSides` 直接进入，其后每次从敌方侧切回玩家侧才自增。

因此 111 的 `TurnNumber <= 1` **只覆盖开战后第一个玩家回合的开始瞬间，每场战斗恰好一次**。额外回合约（如 PaelsEye）中 TurnNumber 已 ≥2，也不触发。

### b. CardThreshold=2 的判定语义

`(decimal)CardsPlayedThisTurn <= DynamicVars["CardThreshold"].BaseValue`：**≤（少于等于）2 张达成**，0 张也触发；出满 2 张仍算；第 3 张把计数器状态打成非 Active。计数在每次玩家回合结束后无条件清零。

注意：官方简中文案写作“打出的牌少于等于…张”、英文为 “or fewer”，与代码语义一致，按原文照搬即可。

### c. DynamicVar / BlockVar / ValueProp 系统

- `DynamicVar(name, baseValue)`：公共构造器 `(string name, decimal baseValue)` 可直接 new（`MegaCrit.Sts2.Core.Localization.DynamicVars/DynamicVar.cs:97`）。`BaseValue` 参与真实计算。
- `RelicModel.CanonicalVars` 是 protected virtual；基类构造器里组装 `DynamicVarSet`（`RelicModel.cs:296`），之后以名字索引：`base.DynamicVars["CardThreshold"]`。
- `BlockVar(block, props)` 固定 Name="Block"，额外携带 `Props`（决定 20 点格挡的价值属性）；20m 即 20 点格挡。获取走 `CreatureCmd.GainBlock(Creature, BlockVar, CardPlay?)` 重载（`decompiled-111/MegaCrit.Sts2.Core.Commands/CreatureCmd.cs:650` 附近）。
- `ValueProp.Unpowered` 注释原文：“Damage from relics, potions, and powers”。所以给遗物格挡带 Unpowered 标记是同类遗物的统一写法（如 `PillarOfCreation.cs:17`、`Shroud.cs:21`）。
- `ValuePropExtensions.IsPoweredAttack()`：

```csharp
if (props.HasFlag(ValueProp.Move)) return !props.HasFlag(ValueProp.Unpowered);
return false;
```

### d. ID 与本地化键推导（双版本兼容的关键前提）

模型 ID 不存字符串常量，而是**由类型名推导**：`ModelDb.GetId(Type)` → `StringHelper.Slugify(type.Name)` 把 PascalCase 转成大写下划线（`MegaCrit.Sts2.Core.Models/ModelDb.cs:510` 附近、`MegaCrit.Sts2.Core.Helpers/StringHelper.cs:95`）。

- `DiamondDiadem` → `DIAMOND_DIADEM`；
- `DiamondDiademPower` → `DIAMOND_DIADEM_POWER`；
- 本地化键：relic 用表 `"relics"`（`RelicModel._locTable = "relics"`），键形如 `DIAMOND_DIADEM.title/.description/.flavor`；power 用表 `"powers"`（`PowerModel.locTable = "powers"`，`PowerModel.cs:23/49/51`），键形如 `<SLUG>.title/.description/.smartDescription`。

**两版本类名相同 ⇒ ModelId 完全一致 ⇒ 键名一致**，回调 mod 无 ID 断裂风险。

## 6. 对“回调 mod”的直接影响汇总

1. 需要在 111 上恢复的行为共四块：出牌计数、回合结束判据与施加 buff、计数器 UI（含 Status 高亮）、交互文本；
2. `DiamondDiademPower` 在 111 不存在 → 必须在 mod 程序集内新建等价 PowerModel 子类（命名建议避开 `DiamondDiademPower` 原名，防未来官方复活同名类时撞 ID；slug 决定 loc 键，改前缀则配套自建键即可）；
3. 幸存的四个生命周期虚方法签名（`AfterSideTurnStart/AfterSideTurnEnd/BeforeSideTurnEnd/AfterCardPlayed`）两版完全一致，适合作为 Harmony 补丁落点；
4. 唯一确认漂移的伤害虚方法：`AbstractModel.ModifyDamageMultiplicative` 由 107 的 5 参（`target, amount, props, dealer, cardSource`）变为 111 的 6 参（末尾追加 `CardPlay? cardPlay`）（`AbstractModel.cs` 107:1580 vs 111:1613）→ 单一 C# override 无法跨版本兼容，须按宿主签名条件挂载不同的 postfix（方案详见 ADR-001）；
5. 111 特有需要**摘除**的东西：`AfterSideTurnStart` 原实现（20 格挡+Blur）、`ExtraHoverTips`（格挡图标悬停提示）。
