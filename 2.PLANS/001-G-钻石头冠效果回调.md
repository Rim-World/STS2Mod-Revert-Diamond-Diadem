# 施工计划：钻石头冠效果回调（RevertDiamondDiadem）

> 目标：在 beta 分支（≥ 某版本，具体见 §3）上把“钻石头冠”（Diamond Diadem）的效果恢复为 default 107 的行为，同时在 default 107 上保持完全无操作（零副作用）。单 DLL 双版本兼容。
> 技术路线（2026-08-27 用户拍板，详见 ADR-001 Accepted 版）：**RitsuLib 0.5.x 框架依赖 + Harmony 补丁化恢复 + mod 程序集内最小自定义 PowerModel 子类（官方原生发现机制）+ RE_ 独立键文本**。default 107 上整个 mod 形态判定不通过、零补丁 no-op。

## 1. 目标行为定义（验收基准）

在“新效果版本”的游戏上运行本 mod 后：

| # | 场景 | 预期 |
|---|---|---|
| A1 | 战斗第 1 回合开始 | **不**获得 20 点格挡、**不**获得残影 buff |
| A2 | 任一回合结束时统计 | 图标旁显示“本回合已出牌数”，≤2 时遗物高亮 Active |
| A3 | 打出第 3 张牌后计数器状态 | 高亮熄灭 |
| A4 | 回合结束且本回合出牌 ≤2 | 获得 buff（HUD 出现图标+tooltip“敌人在本回合造成的伤害减少50%”），计数清零 |
| A5 | buff 存续的下个敌方回合受到攻击卡/怪物攻击伤害 | 伤害 ×0.5（受减伤链 Hook 正常叠加） |
| A6 | 同回合受到毒、HP 流失、遗物/药水直伤等非 Powered 攻击伤害 | 不减半 |
| A7 | 敌方回合结束时 | buff 移除；若下回合仍 ≤2 张牌则重新获得 |
| A8 | 战斗外查看遗物详情 | 描述文本=107 版文案（各语言），悬停不再出现格挡图标提示 |
| A9 | 在 default 107 上加载本 mod | 完全 no-op（无补丁生效），文本不变 |
| A10 | 联机/成就等其他系统 | 不受影响（不改池子、不改事件） |

## 2. 实施阶段

### 阶段 1：骨架搭建
1. 以 `STS2Mod-回调同步/src/RevertSynchronize/` 为目录模板、以 `STS2Mod-达弗修改/src/DarvRelicPoolMod/` 为 RitsuLib 接入模板，建 `9.SRC/RevertDiamondDiadem/`：
   - `project.godot`（Godot 4.5 + C#）、`export_presets.cfg`（export_filter="resources"，列 `res://RevertDiamondDiadem/mod_image.png` + `res://RevertDiamondDiadem/localization/**`）、`build.ps1`、`RevertDiamondDiadem.json`（manifest：min_game_version="0.107.0"，has_pck=true，has_dll=true，affects_gameplay=true，dependencies=[{"id":"STS2-RitsuLib","min_version":"0.5.15"}]）。
   - csproj 引用游戏当前 `$(Sts2DataDir)/sts2.dll` 与 `0Harmony.dll`（Private=false）、NuGet `STS2.RitsuLib`；Krafs.Publicizer 视阶段 2 结论决定是否引入。**编码纪律=只用两版共有成员**（杂耍计数 ADR-003 原则），版本特有成员一律走 Optional/dynamic 补丁目标。
   - `ModEntry.cs`：`[ModInitializer("Initialize")]` → try/catch 全包 → `RitsuLibFramework.CreateLogger` + `ModTypeDiscoveryHub.RegisterModAssembly` → `HostShapeGate` 形态判定（DeclaredOnly 反射，不触 ModelDb/LocManager）→ 仅“新效果版”创建 patcher 注册恢复组补丁并 `ApplyRequiredPatcher(..., DisableMod)`。
3. `HostShapeGate.cs`：判据① DiamondDiadem 自有 AfterSideTurnStart override（DeclaredOnly 查询非空）；判据② 官方 DiamondDiademPower 类型缺失。①&&② ⇒ IsNewEffectVersion=true；否则 mod 静默 no-op 并 Log.Info 原因。

### 阶段 2：两版 API 差异全量核对（写代码前最后一道关卡）
产出 `docs/compat-checklist-reddia.md`（差异表逐行打勾），核对对象：
- `ValuePropExtensions.IsPoweredAttack()` 两版签名；
- 减伤链入口：`Hook.ModifyDamage*` 静态广播器在两版的形状（本次调研中 ModifyDamageHookType 已出现，需确认广播循环如何枚举模型实例）——最终确定 postfix 落点与其参数注入方式（Harmony __0..__5 按 index 注入可绕开命名差异）;
- Creature power 查询 API（HasPower<T>/GetPower<T> 或等价遍历）两版共有性；
- PowerModel 图标资源的关联路径（Id 推导的资源位置 + mod pck 能否提供该路径）;
- DynamicVarSet 构造时机 vs 我们对 CanonicalVars 的 postfix 生效顺序;
- 敌我双方 participant 序列、ThrowingPlayerChoiceContext 等 111 特有类型在我们不触碰它们时的无关性确认。
每项给出结论：可用/绕道/放弃换路。

### 阶段 3：代码实现
新建文件（全部挂 Revert 前缀命名空间，避免与未来官方复活类撞 ID）：

1. `Models/RevertDiamondDiademPower.cs`
   - `class RevertDiamondDiademPower : PowerModel`，仅 override 两版稳定的 abstract：`Type => Buff`、`StackType => Single`；
   - slug → `REVERT_DIAMOND_DIADEM_POWER` → 键在 mod 自己 pck 的 powers.json 中提供 title/description(/smartDescription)，内容照抄 107 官方文案（§4 文本资产）；
   - 移除时机 `AfterSideTurnEnd(side==Enemy)` 是四钩子之一、两版签名一致 → 直接在此 override 写（比 patch 更稳）；注意 override 时方法体只引用共有 API。
   - 减伤数值**不在子类里 override**（ModifyDamageMultiplicative 签名漂移），由 §3.2 补丁实现并判定“target 拥有本 buff”。
2. `Patches/DiademStateGate.cs` — 形状守卫 + 版本形态判定：
   - 判据①（新效果版本）：`AccessTools.Method(typeof(DiamondDiadem), "AfterSideTurnStart")` 的 DeclaringType == typeof(DiamondDiadem)；
   - 判据②（原专属 power 不存在）：`AccessTools.TypeByName("...DiamondDiademPower")` 为 null（防未来复活时双注册）；
   - 两者同时成立才挂载“恢复组”补丁；否则记录原因并整体禁用（107 上自动走此分支 = no-op）。
3. `Patches/RestoreCounterPatches.cs` — 计数 UI 组（条件挂载到 DiamondDiadem 实例相关点）：
   - `RelicModel.AfterCardPlayed` postfix：仅当 `__instance is DiamondDiadem` 且激活 → `_counter[__instance]++` + RefreshStatus()；
   - `RelicModel.ShowCounter` postfix on DiamondDiadem（DeclaringType=RelicModel 的虚声明处挂、“对象属于头冠则改值”）或直接 target 用 DiamondDiadem 类型查找（该成员在 111 的 DiamondDiadem 上未 override，必须打基类声明，postfix 内 type-check）；
   - `DisplayAmount` 同法读取计数；
   - 计数容器：静态 `ConditionalWeakTable<RelicModel, StrongBox<int>>`（战斗实例生命周期安全），不入存档。
4. `Patches/RestoreTriggerPatch.cs` — 触发逻辑组：
   - `DiamondDiadem.AfterSideTurnStart` prefix（该方法在 111 由本体自己声明 → 直接命中）：放行返回 false 即短路 20 格挡+Blur 原实现；顺带清理遗留 Blur（若同局先装旧版测试过产生残留的场景不需要——按理论不会有）；
   - `DiamondDiadem.ExtraHoverTips`（111 本体 override）prefix 置空：去掉格挡图标提示；
   - `RelicModel.BeforeSideTurnEnd` postfix（基类声明处挂，type-check DiamondDiadem）：复刻 107 判定——读计数 ≤2 → `Flash(); await PowerCmd.Apply<RevertDiamondDiademPower>(...)`；无条件清零;（异步等待需要用 continuation 形态包装 task 的 postfix——参考回调同步对 async 原 impl 的 Prefix 替换写法）；
   - `DynamicVar("CardThreshold", 2m)` 注入：优先候选=对 `RelicModel.CanonicalVars` getter 在 DiamondDiadem 上的求值做替换（constructor 期生效的问题见阶段 2 核对项 5），退路=保留 111 Block var 并追加 CardThreshold（文本渲染两者互不干扰）；再退路=文本里弃用 `{CardThreshold}` 占位符改硬编码"2"（有损方案，最后才考虑）。
5. `Patches/HalfDamagePatch.cs` — 减伤组：
   - 同时定义 PostfixV5 / PostfixV6 两个静态后缀（分别带 5 参/6 参 Harmony 参数注解形态）；
   - 启动时探测宿主 `AbstractModel.ModifyDamageMultiplicative` 的 ParameterCount（或目标签名匹配）选择其一挂载到同一 MethodBase；若该方法的声明结构特殊则回退到广播器 patch（阶段 2 结论决定）；
   - postfx 体：`if (!gate.On) return; if (target == null) return; if (target 未持有 RevertDiamondDiademPower) return; if (!props.IsPoweredAttack()) return; __result *= 0.5m;`（零分配快速路径，先判 gate 再查表）。
6. 若阶段 2 发现图标资源路径无法由 mod pck 提供 → 采用 fallback：power 实体照常（HUD 有名字/层数文本），图标显示默认占位（观察 BaseLib 怎么给 custom power 配图并抄其思路但不依赖之）。

## 3. 版本启用策略

- 语义判断优先于版本号：形状判据①②(§3.2)本身就等价于“当前是 111 式实现”——110/109 等其它 beta 版若恰好也是新效果则同样被正确处理，若是旧效果则自动 no-op；
- SemVer 门作为第二保险（假设范围 Minor>=108 才尝试激活；具体区间待检查 108~110 反编译树后收紧——decompiled-full(v110) 已在本机可查）；
- 该策略下无需用户配置项。

## 4. 风险登记簿

| 风险 | 影响 | 对策 |
|---|---|---|
| ModifyDamageMultiplicative 广播结构两版不同 | 减伤失效或双重打折 | 阶段 2 先核广播器;按 index 参数注入规避形参差异;Postfix 只乘系数幂等性控制 |
| CanonicalVars postfix 赶不上 ctor | {CardThreshold} 占位符渲染失败 | 三级退路见 §3.4;最坏换硬编码文案 |
| loc 合并顺序未证 | 与其他覆写同官键的 mod 冲突 | 全部用 RE_ 独立键规避 |
| 未来官方复活 DiamondDiademPower 类名 | 双 ModelId 冲突 | 自定义类带 Revert 前缀 + 守卫判据②检测即禁用 |
| 存档兼容（107 存了 relic，切 111 读档） | _cardsPlayedThisTurn 字段消失的序列化差異 | 我们不复用该字段;ConditionalWeakTable 独立计数 |
| 108~110 形态未知 | 误启用/漏启用 | 判据是行为级而非版本号级;上线前抽查 decompiled-full |
