# 001 总体设计：钻石头冠效果回调（RevertDiamondDiadem）

- 版本：对应 mod 版本 1.0.0
- 依据：`9.SRC/RevertDiamondDiadem/` 现有源码、`1.ADR/001-钻石头冠回调技术路线选型.md`、`3.DOCS/` 四篇调研与取证文档
- 说明：本文只记录源码与既有文档能够支撑的设计事实；无法从源码或文档确认的内容标为「未记录」。

## 1. 设计目标

1. 在钻石头冠已是 beta 111 式新效果（战斗开始获得 20 点格挡 + 1 层残影）的宿主上，把该遗物的行为恢复为 default 107 的旧效果：每个玩家回合结束时统计本回合出牌数，不超过 2 张则施加专属减伤 buff，持续到该次敌方回合结束。
2. 在钻石头冠本来就是旧效果的宿主（如 default 107）上，整个 mod 不产生任何补丁与副作用。
3. 不改动官方遗物类源码、不新增遗物、不替换遗物池：直接修正原遗物的行为与展示。
4. 单 DLL 覆盖 107 式与 111 式两种宿主形态，不做条件编译，不发双变体包。

## 3. 模块划分

源码按「入口 / 形态判定 / 模型 / 补丁」四层组织：

| 模块 | 文件 | 职责 |
|---|---|---|
| 入口 | `ModEntry.cs` | 注册 mod 程序集、创建日志器、执行形态判定、按判定结果创建 patcher 并注册补丁组、申请应用补丁并在必需补丁失败时禁用整个 mod |
| 形态判定 | `HostShapeGate.cs` | 只用 `Type.GetType`/反射枚举判定宿主实现形态，不触碰 `ModelDb`/`LocManager`；对外暴露 `Active`/`IsNewEffectVersion`/`Disabled` 与 `Evaluate`/`Disable` |
| 模型 | `Models/RevertDiamondDiademPower.cs` | 重建被官方在 111 删除的专属 buff 实体，只 override 两版稳定的 `Type`/`StackType` 与 `AfterSideTurnEnd` |
| 补丁 | `Patches/DiademVanillaHooksPatches.cs` | 短路 111 版遗物本体的 `AfterSideTurnStart`；摘除 `ExtraHoverTips` 的格挡提示 |
| 补丁 | `Patches/RestoreCounterPatches.cs` | 出牌计数、计数 UI、回合结束判定与 buff 施加，以及计数状态容器 `DiademState` |
| 补丁 | `Patches/HalfDamagePatch.cs` | 在 `AbstractModel.ModifyDamageMultiplicative` 上做减半 |
| 补丁 | `Patches/LegacyRelicDescriptionPatch.cs` | `RelicModel.Description` 改读本 mod 独立键 |
| 补丁 | `Patches/PowerIconPatches.cs` | 自定义 buff 的两个图标路径改指官方原类资源 |

补丁注册顺序即 `ModEntry.Initialize` 中的顺序：`SideTurnStartBypassPatch`、`BlockHoverTipRemovalPatch`、`CardCounterPatch`、`TurnEndTriggerPatch`、`ShowCounterUiPatch`、`DisplayAmountUiPatch`、`HalfDamagePatch`、`LegacyRelicDescriptionPatch`、`PowerSmallIconPatch`、`PowerBigIconPatch`，共 10 个 `IPatchMethod` 实现，挂在同一个 patcher（id `revert_main`）下。

## 4. 启用策略：行为级形状守卫

`HostShapeGate.Evaluate` 从两个判据推断宿主形态：

1. **判据①**：`MegaCrit.Sts2.Core.Models.Relics.DiamondDiadem` 是否**自己声明**了 `AfterSideTurnStart`（`DeclaredOnly` 查询）。111 版由遗物本体声明该方法，107 版没有。
2. **判据②**：全 AppDomain 内是否还能找到官方 `MegaCrit.Sts2.Core.Models.Powers.DiamondDiademPower` 类型。若未来官方复活该类，本 mod 再注册同名语义的 buff 会造成 ModelId 冲突，因此一并停用。

判定结果 `IsNewEffectVersion = ① && !②`：

- `false`：记录日志并直接返回，不创建 patcher，mod 为零补丁 no-op。
- `true`：创建 patcher 并注册全部补丁。
- 找不到 `DiamondDiadem` 类型：`Disabled = true`，同样 no-op。

该策略不使用版本号，因此 108~110 等未逐一排查的版本也能按实际实现形态自适应。每个补丁体内还有 `if (!HostShapeGate.Active) return;` 的第二道保险，即使补丁被应用、形态在运行期失效也不会改动行为。

额外的失败处理：`RitsuLibFramework.ApplyRequiredPatcher(patcher, onFailure)` 在必需补丁应用失败时回调 `HostShapeGate.Disable()`，使全部补丁退回直通。

## 5. 补丁策略与数据流

### 5.1 出牌计数

`CardCounterPatch` 在 `RelicModel.AfterCardPlayed(PlayerChoiceContext, CardPlay)` 上做 postfix，仅当实例是 `DiamondDiadem`、出牌者为遗物拥有者、且 `CombatManager.Instance.IsInProgress` 时 `DiademState.Increment` 并刷新状态。

计数不写入遗物实例字段，也不进存档：`DiademState` 用 `ConditionalWeakTable<DiamondDiadem, StrongBox<int>>` 以遗物实例为键持有，随实例回收。阈值硬编码为 `2m`（`DiademState.Threshold`），复刻 107 的 `CardThreshold` 初值。

### 5.2 计数 UI

- `ShowCounterUiPatch`：postfix `RelicModel.ShowCounter`，仅对 `DiamondDiadem` 返回 `CombatManager.Instance.IsInProgress`，即战斗外不显示计数器。
- `DisplayAmountUiPatch`：postfix `RelicModel.DisplayAmount`，返回当前计数。
- `DiademState.RefreshStatus`：按「计数 ≤ 阈值」把 `RelicStatus` 置 `Active` 或 `Normal`，随后调用 `InvokeDisplayAmountChanged` 刷新数字。施加与清零两条路径都必须调用，否则 UI 会停在旧值（2026-08-28 首轮验收实测）。

这两个成员在 111 版的 `DiamondDiadem` 上已删除 override，因此目标必须选 `RelicModel` 的基类声明，再在 postfix 内按实例类型过滤。

### 5.3 回合结束结算

`TurnEndTriggerPatch` 是 prefix 全替换形态：命中 `DiamondDiadem` 时把 `__result` 换成自写的 `RunAsync`，返回 `false` 跳过原实现。

`RunAsync` 的判定顺序：

1. 当前结算方 participants 含遗物拥有者的战斗生物；
2. 读取本回合计数，若 ≤ `Threshold` 则 `Flash()` 并通过 `PowerCmd.Apply<RevertDiamondDiademPower>` 施加 1 层；
3. 无论是否施加，都清零计数并 `RefreshStatus`（复刻 107 的「无条件清零」语义）；
4. `PowerCmd.Apply` 包在 try/catch 内，失败只记日志，不打断战斗流程；
5. 首次触发时打印一行 `turn-end trigger live, cards played this turn = N` 作为链路活性探针。

### 5.4 减伤

`HalfDamagePatch` 的 postfix 作用在 `AbstractModel.ModifyDamageMultiplicative` 上，命中条件依次为：mod 处于 Active、`__instance` 是 `RevertDiamondDiademPower`、`target` 就是 buff 拥有者、`props.IsPoweredAttack()` 为真。全部满足时 `__result *= 0.5m`。毒、HP 流失、遗物/药水直伤等非 Powered 攻击路径不受影响。

该虚方法在两个版本上签名不同（107 五参 / 111 六参，末尾多一个 `CardPlay?`），单一 override 无法横跨。补丁声明两条 `PatchTarget.OptionalMethod` 精确签名目标，命中其一即可；postfix 通过形参名 `target`/`props` 注入，两份签名共用同一份逻辑。

### 5.5 buff 实体与生命周期

`RevertDiamondDiademPower : PowerModel`：

- `Type => PowerType.Buff`、`StackType => PowerStackType.Single`；
- `AfterSideTurnEnd(side == CombatSide.Enemy)` 时 `PowerCmd.Remove(this)`——buff 只覆盖施加后的那个敌方回合，敌方回合结束即移除（漏写该 override 会导致永久常驻，2026-08-28 实测）；
- 减伤数值不在本类实现，原因见 5.4；
- 类名带 `Revert` 前缀，使推导出的 slug 为 `revert_diamond_diadem_power`，避免与未来官方复活的原类撞 ModelId。

### 5.6 表现层

- **描述文本**：`LegacyRelicDescriptionPatch` postfix `RelicModel.Description`，对 `DiamondDiadem` 返回 `new LocString("relics", "RE_DIAMOND_DIADEM.description")`。用独立键而非覆写官方 `DIAMOND_DIADEM.description`，避免与其他 mod 竞争同一键的合并顺序问题。
- **图标**：游戏按类名 slug 推图标路径，`revert_diamond_diadem_power` 在官方包里不存在，会回落占位图。`PowerSmallIconPatch`/`PowerBigIconPatch` 分别 postfix `PowerModel.PackedIconPath` 与 `ResolvedBigIconPath`，改写为官方原类资源 `res://images/atlases/power_atlas.sprites/diamond_diadem_power.tres` 与 `res://images/powers/diamond_diadem_power.png`。这两套资源在 107/111 官方包中均未删除，mod 因此不自带任何图片。
- **悬停提示**：`BlockHoverTipRemovalPatch` 把 111 版新增的格挡提示 `ExtraHoverTips` 置空，与减伤语义保持一致。

### 5.7 端到端数据流

```
出牌 → RelicModel.AfterCardPlayed (postfix) → DiademState.Increment + RefreshStatus
                                              → 遗物旁数字刷新、≤2 时高亮
回合结束 → RelicModel.BeforeSideTurnEnd (prefix 替换)
        → 计数 ≤2 ? Flash + PowerCmd.Apply<RevertDiamondDiademPower>
        → 清零 + RefreshStatus
敌方回合受到 Powered 攻击 → AbstractModel.ModifyDamageMultiplicative (postfix) → ×0.5
敌方回合结束 → RevertDiamondDiademPower.AfterSideTurnEnd → PowerCmd.Remove
```

## 6. 异常处理

| 位置 | 手段 | 失败后的外部表现 |
|---|---|---|
| `ModEntry.Initialize` 全体 | 外层 try/catch + `Log.Error` | 加载失败但游戏继续运行 |
| 形态判定 | 类型缺失即 `Disabled`；判据不成立即提前 return | mod 静默无操作，日志给出原因 |
| 补丁应用 | `ApplyRequiredPatcher` 的失败回调 → `HostShapeGate.Disable()` | 所有补丁体内快速检查失效，行为回到原版 |
| 单个补丁 | 每个方法体先判 `HostShapeGate.Active` 再做实例类型判断 | 不满足即直通原实现 |
| 补丁目标 | 版本特有成员一律 `PatchTarget.OptionalMethod`（目标不存在时忽略） | 目标缺失不阻断整组补丁 |
| buff 施加 | `PowerCmd.Apply` 外包 try/catch | 记日志、战斗继续 |

补丁的 `IsCritical` 标记：`SideTurnStartBypassPatch`、`CardCounterPatch`、`TurnEndTriggerPatch`、`HalfDamagePatch` 为 `true`；文本、图标、计数器 UI、悬停提示四个补丁为 `false`。该标记由 RitsuLib 判定失败是否算「必需补丁失败」。

## 7. 兼容性设计

- **版本自适应**：启用判定基于宿主实现形态而非版本号，见第 4 节。
- **编码纪律**：只引用两个版本共有的成员；版本特有成员（如 `ModifyDamageMultiplicative` 的不同参数表）经 Optional 精确签名目标进入。
- **文本兼容**：本地化为 16 种语言（deu/eng/esp/fra/ind/ita/jpn/kor/pol/ptb/rus/spa/tha/tur/zhs/zht）。其中 13 种取自 v0.107.1 官方文本；zht 由 zhs 转写；tha 仅 `title` 回落 eng（107 官方泰语缺该键）；ind 全部回落 eng。
- **明确不保证**：盗版、修改版、移动版、过旧版本，以及冷门或次级 mod 的组合兼容性。

## 8. 构建与打包

`9.SRC/RevertDiamondDiadem/build.ps1` 三步流水线：

1. `dotnet build RevertDiamondDiadem.csproj -c Debug -p:NuGetAudit=false`，产物固定从 `.godot/mono/temp/bin/Debug/` 取 `dll` 与 `pdb`；
2. `godot --headless --import --path <root>` 生成导入元数据，再 `--export-pack "Windows Desktop"` 导出 `RevertDiamondDiadem.pck`；
3. 把 `dll`、`pdb`、`RevertDiamondDiadem.json` 与 `pck` 拷入游戏 `mods/RevertDiamondDiadem/`。

`export_presets.cfg` 采用 `export_filter="selected_resources"`，显式列出 `res://RevertDiamondDiadem/mod_image.png` 与 16 个语言目录下的 `relics.json`/`powers.json`。Godot 工程要求目录内存在 `.sln`，故仓库内保留了 `RevertDiamondDiadem.sln`。

## 9. 测试方案与记录

验收基准见 `2.PLANS/001-G-钻石头冠效果回调.md` §1 的 A1~A10 场景表（开局不获得格挡与残影、计数器显示与高亮、回合末触发、Powered 攻击减半、非 Powered 伤害不减半、敌方回合结束移除、描述与悬停提示、旧效果宿主完全 no-op、不影响联机与成就等系统）。

实际执行方式为：构建安装后在游戏内按场景表人工验收，共三轮反馈修正（见 `1.ADR/001-钻石头冠回调技术路线选型.md` 后续记录 2~4）。源内无自动化测试工程，单元测试与性能指标：未记录。
